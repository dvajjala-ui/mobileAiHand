# Product-development checkpoints

Last updated: 2026-10-26 (Asia/Kolkata)

These gates turn the [five-stage findings](reviews/phone_only_mvp/consolidated_review_report.md) into a build order. Each checkpoint should leave the Android app buildable. Acceptance criteria are proposed engineering targets until a real-device trial confirms them. Record the S24 Ultra Android version, app versions, exact model file, and observed results without storing private task content.

| Checkpoint | Status | Exit evidence | Related issues |
| --- | --- | --- | --- |
| C0 — Source and safe Settings trial | Open | Project is committed; build/tests run from a clean checkout. The Accessibility service declares gesture capability. A Settings-only trial cannot type, switch to another app, or trigger an external action. | EGM-01, EGM-02, EGM-03 |
| C1 — Local model feasibility on S24 Ultra | Blocked on C0/device | Five consecutive offline Settings version reads match the visible Android Settings value; no unauthorized action or process kill. Record model load, per-action delay, total duration, RAM behavior, and battery effect. Proposed usability targets: load ≤60 seconds, median action decision ≤15 seconds, total task ≤3 minutes. If missed, reassess model choice before expanding app flows. | EGM-04, EGM-05 |
| C2 — Typed task and constrained controller | Blocked on C1 | One chosen guided task has an explicit TaskSpec, allowed package/screen/action matrix, fresh-node check, cancellation check before every action, and a one-use final-action rule. Adversarial screen text and opaque controls cannot cause an unapproved action. | EGM-06, EGM-07, EGM-08 |
| C3 — Honest outcomes and privacy | Blocked on C2 | New result evidence is correlated with the task; interruption after a possible final tap reports `uncertain` and never retries automatically. No raw UI text, model reply, credential, photo URI, or message body persists in the task log or legacy preferences. | EGM-09, EGM-10, EGM-11 |
| C4 — Safe guided dry runs | Blocked on C2–C3 | Reddit fields appear in a draft without publishing. WhatsApp preview shows exact recipient and selected thumbnails without sending. Tests cover zero, one, 30, and more than 30 photos, permission states, midnight boundary, missing media, and ambiguous contacts. | EGM-12, EGM-13 |
| C5 — First complete agent task | Blocked on C1–C3 | Proposed first task: ask an exact question in the ChatGPT app and report a newly observed answer tied to that question. Signed-out, no-network, timeout, and prior-answer screens produce honest non-success states. Initial Run approval must explicitly say the question will be sent through ChatGPT. | EGM-14 |
| C6 — One approved publish/send workflow | Blocked on C4–C5 and product decision | Choose **either** Reddit publish **or** WhatsApp send first. Exact target/payload and photo identities are checked at the final boundary; user approval follows the chosen consent rule; success is observed or marked uncertain. Cancel, changed target, and interrupted post-tap cases cause no duplicate attempt. The other workflow remains disabled until its own tests pass. | EGM-08, EGM-09, EGM-15 |
| C7 — Wider prompt input and distribution | Blocked on C6 | Supported natural-language intents map to typed tasks and ask for missing details. CI builds and tests a clean checkout. Decide public distribution, Android permission policy, model delivery, and future laptop-submission/backend needs separately. | EGM-16, EGM-17 |

The local model trial is the first major feasibility gate. The current app has a buildable debug APK and six parser/resolver unit tests, but those results do not satisfy C0 or C1. The first release can stop at C5 or at one C6 workflow once its scope is explicitly chosen; it should not claim all requested app actions work just because their forms exist.
