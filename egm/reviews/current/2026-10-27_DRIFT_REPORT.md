## phone_only_mvp.md

- The **Current implementation and dependencies** section describes a prompt form, cross-app Accessibility loop, share intents, uninstall flow, media permission, and six unit tests. The current `MainActivity` exposes only a Settings version trial; the manifest requests no media permission; `PhotoInventory` is unused; and the test sources now contain ten unit tests. Update this historical description before using the design as a current implementation guide.
- The proposed `TaskSpec`, `TaskState`, `TaskCoordinator`, `TaskPolicy`, `PendingExternalAction`, `OutcomeVerifier`, and `TaskLog` do not exist in `android-app/app/src/main/java/ai/mobileaihand/`. The current `SettingsTrialPolicy` covers only safe navigation within Android Settings. Guided ChatGPT, Reddit, WhatsApp, and uninstall tasks, their final approvals, and their outcome states remain unimplemented.
- The design allows 16 agent actions for a typed task, while `SettingsTrialPolicy.MAX_ACTIONS` is 8. The narrower cap is deliberate for the current trial, but the design does not distinguish that trial limit from the proposed later task limit.
- The Settings postcondition promises to read the exact version from the screen and show it with its label. `PhoneControlService` instead reports `Build.VERSION.RELEASE` after `SettingsTrialPolicy.versionVisible` finds a nearby matching value in Accessibility labels. It does not capture an independent screen value or perform the design's second observation. No S24 Ultra trial has established that this check works on the target phone.
- The model-import phase calls for a compatibility check before promotion and rollback to the last working model. `ModelStore` checks free space and copy completeness and uses a temporary file, but it replaces `local-model.task` before `LocalModel` tests compatibility. An incompatible `.task` can therefore replace a working model.
- The photo workflow calls for timestamps, a thumbnail preview, removal, a frozen approved URI set, and a WhatsApp share payload. `PhotoInventory.today` returns only URIs, and no current UI calls it. The manifest has no photo permission and there is no active send/select flow.
- The delivery phase calls for Android instrumentation coverage and `.github/workflows/android.yml`. The repository has only JVM unit-test sources under `android-app/app/src/test/` and no Android instrumentation tests or GitHub Actions workflow.
